# Evidence RAG v1 specification

Status: defined planning scope for a future execution chat; no implementation or measured results exist. This specification settles the open implementation choices in the original README. Work only in `/Users/matthewgoralczyk/BentoLabs/portfolio/evidence-rag`.

## Product and acceptance

Build a local document question-answering demonstration over original fictional equipment manuals. A reader asks a question, sees a bounded answer with exact source quotations, opens the cited current passage, and understands when the evidence is insufficient. A maintainer can publish a replacement, rebuild an index, and delete a document. A persistent label identifies fixture/extractive versus actual local-model execution.

- A1: A clean local checkout starts on API 8115 and web 5115 with deterministic fixtures, two demo identities, a supported answer and a working passage viewer.
- A2: BM25, dense, hybrid RRF and hybrid-reranked retrieval are separate selectable pipelines with common chunks, authorised candidates and K=5 outputs.
- A3: Reader access cannot expose restricted content through search, ranking statistics, titles, snippets, citations, cache hits, history, jobs, logs or responses racing a mutation.
- A4: Replacement publishes all new retrieval surfaces atomically; deletion removes retrievable content and cached responses before its success response is sent. Old citations cease working in ordinary answer routes.
- A5: Actual local inference is optional and explicit; fixture metrics never claim model quality. Reproducible evaluations hold generation fixed and report access regressions separately.
- A6: The responsive, keyboard-operable application supports both themes, loading, empty, denied, stale, failed-job and model-busy states.
- A7: Strict Python and TypeScript checks include test files; offline CI and a browser-to-real-API flow pass before a fixture-complete claim.
- A8: A runbook and small evidence report reproduce setup, replacement, deletion, evaluation and known limitations without private material.

No external connectors, deployment, production identity provider, fine-tuning, OCR, PDF ingestion, agent tools or customer documents are in v1. Local reversible implementation is authorised only when Matthew pastes the execution prompt. Publishing, pushes, deployment, model uploads and paid compute need specific authorisation.

## Runtime and boundaries

Python 3.12.x, `requires-python = ">=3.12,<3.13"`, uv, FastAPI, Pydantic, sqlite3/FTS5 and NumPy; React, strict TypeScript and Vite. Node 24 LTS is the CI target. The machine already has uv Python 3.12.14, but executors verify it. Resolve actual dependencies at bootstrap and commit `uv.lock` and `web/package-lock.json`; this plan invents no package pins. Optional `ml` dependencies are torch, transformers, sentence-transformers and huggingface-hub; psutil monitors the model worker.

Bind API to `127.0.0.1:8115`, web to `127.0.0.1:5115`, use Vite strictPort and exact credentialed CORS origin `http://127.0.0.1:5115`. Validate Host for the API and Origin for state-changing requests. Use one API process and one internal queued worker; multiple Uvicorn workers are unsupported. Each shell operation sets the absolute child workdir. Data, HF cache, model snapshots, logs and SQLite WAL files live beneath this child's ignored `.runtime/`; no shared mutable database or model cache.

Limits: 50 documents, 200 retained versions, 2,000 active or staged chunks, 20 MiB total retained text, 256 KiB UTF-8 Markdown per import, 500 characters per question, 5 final passages, 20 candidates per retriever, 20 reranker pairs, 4 model batch items, 4 CPU inference threads, one active model subprocess, 8 pending indexing jobs, 2 queued interactive model requests. Exceeding admission limits returns 413 or 429 before starting work. Model wall timeout is 90 seconds/request and 10 minutes/index job; a watchdog terminates its own child after 6 GiB RSS or deadline. These are application limits, not predictions of speed or memory use.

## Owned corpus and split

Create 12 fictional logical documents, each with 8 named sections of 80-160 words: 8 reader manuals and 4 maintainer appendices. Domain: the invented Aster bench-top circulation trainer; include a conspicuous fictional demonstration notice. No real machinery instructions or copied manual text. Manifest records owner, MIT provenance, logical ID, version ID, date, minimum role, source SHA-256, section anchors and lifecycle state.

Each document starts with active v2 and superseded v1; a separate deleted calibration-bulletin tombstone has no text. The public `circulation` manual changes a fictional display limit from 30 to 35 units. Restricted `calibration` has an obvious secret fixture string `MAINTAINER-CAL-7391`. One public source includes a quoted malicious instruction to reveal the appendix; treat it as source text without authority. No source string becomes a tool call, system message or database identifier.

Question set: 72 manually authored items, 24 development and 48 frozen test. Development: 12 supported, 4 unsupported, 4 version-conflict, 4 restricted. Test: 24 supported, 8 unsupported, 8 version-conflict, 8 restricted. Group by section family AND question template; no held-out section family or template appears in development labels. All documents remain indexed because this is retrieval, not supervised model training. Each item records identity, expected abstention, relevant current section IDs, expected atomic facts and forbidden strings. Stable section IDs, not ephemeral chunk IDs, define relevance. Record exact corpus and question-file hashes before evaluation; any edit creates a new evaluation revision.

## Authoritative access and demo sessions

Two identities: `reader` (role `reader`) and `maintainer` (role `maintainer`, also the administrator). Reader can access active reader documents. Maintainer can access all active documents and explicit superseded-version history. Role is stored server-side; client user/role headers are ignored. This is an explicit loopback demonstration, not production authentication.

At local bootstrap generate separate 256-bit launch codes per identity, print each once in the local terminal, store only SHA-256 code digests in `.runtime/demo-codes.json` with mode 0600. `POST /api/session` accepts `{code}` plus the exact web Origin; compare digests in constant time, never accept an identity as proof. Each success creates a fresh random opaque session ID and CSRF token. Store only the session hash in SQLite. Cookie `evidence_session`: HttpOnly, SameSite=Strict, Path=/, Max-Age=3600; Secure=false solely for loopback HTTP. The UI asks for the printed code and displays the server-returned identity. Logout removes the session and clears cookie/client state. Five failed logins per 60 seconds per loopback source cause 429. Secrets are never logged.

Every state-changing authenticated route requires exact Origin, the session cookie and `X-CSRF-Token` equal to the session's token. GET `/api/session` returns that token only for a valid session and is not cacheable. JSON body size is bounded before parsing. All application responses use `Cache-Control: no-store`. No source text goes into URLs, query logs, browser storage or persisted analytics. Invalid sessions return 401. Admin actions by readers return 403. Missing, deleted, superseded or forbidden ordinary documents/citations all return the same 404 envelope.

A single `AccessScope(user_id, role, epoch)` is resolved from the session and database on each request. Roles can only change through the local reset/bootstrap command in v1; reset revokes every session. Minimum document role can change via an admin replacement. Apply policy before candidate scoring, before reranking/generation, before cache return, on passage opens and immediately before response publication. Admin-only job/history endpoints check the session before looking up IDs. Public health has no counts or corpus metadata. Metrics are CLI-only; HTTP logs contain route templates, status, request ID and duration only.

## Storage and transaction contract

Use SQLite WAL, foreign_keys=ON, busy_timeout=5000 and numbered SQL migrations. IDs are UUID strings except content-addressed chunk IDs. UTC timestamps use ISO-8601. Required tables and constraints:

- `meta(singleton INTEGER PRIMARY KEY CHECK(singleton=1), schema_version INTEGER, reader_epoch INTEGER, maintainer_epoch INTEGER)`.
- `users(id TEXT PRIMARY KEY, role TEXT CHECK(role IN ('reader','maintainer')), enabled INTEGER CHECK(enabled IN (0,1)))`.
- `sessions(token_hash TEXT PRIMARY KEY, user_id TEXT REFERENCES users, csrf_token TEXT, expires_at TEXT)`.
- `documents(id TEXT PRIMARY KEY, title TEXT, min_role TEXT CHECK(min_role IN ('reader','maintainer')), active_version_id TEXT NULL, deleted_at TEXT NULL, revision INTEGER NOT NULL)`; enforce active-version ownership in the repository transaction and test it.
- `versions(id TEXT PRIMARY KEY, document_id TEXT REFERENCES documents, label TEXT, effective_date TEXT, status TEXT CHECK(status IN ('staged','active','superseded','deleted')), text TEXT NULL, sha256 TEXT, UNIQUE(document_id,label))`; partial unique index permits one active version per document.
- `chunks(id TEXT PRIMARY KEY, version_id TEXT REFERENCES versions, section_id TEXT, start_char INTEGER, end_char INTEGER, text TEXT, CHECK(start_char>=0 AND end_char>start_char))`; text equals the exact version substring, offsets count Python Unicode code points.
- `vectors(chunk_id TEXT PRIMARY KEY REFERENCES chunks ON DELETE CASCADE, model_revision TEXT, dim INTEGER CHECK(dim=384), vector BLOB)`; little-endian float32, length exactly 1536 bytes, finite and L2-normalised (zero vectors rejected).
- `fts_reader` and `fts_maintainer`: independent FTS5 tables `(chunk_id UNINDEXED, text, tokenize='unicode61 remove_diacritics 2')`. Reader table contains active reader chunks only; maintainer contains all active chunks. Role-specific statistics prevent restricted material changing reader BM25 ordering.
- `jobs(id TEXT PRIMARY KEY, kind TEXT CHECK(kind IN ('import','replace','rebuild')), document_id TEXT, expected_revision INTEGER, status TEXT CHECK(status IN ('queued','running','succeeded','failed','cancelled')), payload_json TEXT NULL, error_code TEXT NULL, created_at TEXT, updated_at TEXT)`; payload is private staged input, never an API field.
- `answer_cache(key TEXT PRIMARY KEY, user_id TEXT REFERENCES users, role TEXT, epoch INTEGER, payload_json TEXT, expires_at TEXT)`; at most 128 entries, 5-minute TTL; implement only after epoch checks exist, otherwise keep caching disabled.

Create/replacement jobs validate and stage text, calculate chunks/vectors outside the write transaction, then `BEGIN IMMEDIATE`: verify expected document revision and job not cancelled; retire old active chunks from both FTS tables and vectors; mark old version superseded; install new active version/chunks/vectors/FTS; update minimum role; increment affected role epochs; delete affected role caches; mark job succeeded and clear payload; COMMIT. A failed job leaves the previous active version usable. No partially indexed version is queryable. Reader-document changes increment both epochs; maintainer-only changes increment maintainer epoch. A public-to-restricted or restricted-to-public change increments both.

Rebuild uses a snapshot of current versions and role epochs, builds a complete replacement in bounded worker memory, then checks the snapshot in one write transaction before replacing all indexes; mismatch produces `stale_job` without publication. Delete is synchronous: acquire publication lock, cancel jobs targeting the document, clear their payload, delete all chunk/vector/FTS rows for every version, null all version text, mark versions and document deleted, increment epochs, clear affected caches, commit and send success. Audit tombstones retain IDs/hashes/dates only. No source uploads are stored outside SQLite. Logical removal is promised; forensic erasure of disk/WAL or information already shown to a user is not.

The API owns an `asyncio.Lock` for mutation commit and final response publication. Retrieval/generation runs outside it with captured role epoch. Under the lock, check session, permissions, each returned chunk and epoch again; send the complete ASGI response body while still holding the lock. If the epoch changed, discard the result and return 409 `corpus_changed`, including no passages. Cache reads follow the same path. Mutations also send their success body under this lock. This defines ordering at server response publication, not physical browser receipt. Single-process deployment is a required condition. Delete/cancel wins over a staged worker's later commit.

## Retrieval, answer and citation contracts

Shared Pydantic models (`extra='forbid'`): `Role = Literal['reader','maintainer']`, `RetrievalMode = Literal['bm25','dense','hybrid','hybrid_rerank']`, `GenerationMode = Literal['extractive','local']`, `QuestionRequest(question: str, retrieval_mode: RetrievalMode, generation_mode: GenerationMode)`, `Citation(chunk_id, document_id, version_id, title, version_label, effective_date, section_id, start_char, end_char, quote)`, `Answer(request_id, execution_profile, retrieval_mode, generation_mode, answer: str, abstained: bool, reason: str | None, citations: list[Citation], timings_ms: dict[str,float])`, and `ErrorDetail(code: str, message: str, request_id: str)` and `ApiError(error: ErrorDetail)`. All Citation IDs/title/labels/dates/section/quote are strings; offsets are nonnegative integers. Answer request_id/profile/modes are strings constrained to their enums. Do not expose raw model logits, hidden corpus counts or role epochs in public responses. Generated TypeScript types come from the committed OpenAPI snapshot; runtime parsing uses Zod schemas matching it.

Chunk Markdown by headings and exact character offsets, windows of at most 160 whitespace tokens / 1,000 characters with 32-token overlap; never cross section boundaries. Split an overlong token at the character bound. IDs are SHA-256 of version ID, section, offsets and chunker revision. Empty/invalid UTF-8, binary, HTML script blocks and documents without headings are rejected with 422. Markdown is displayed as escaped text; no raw HTML or remote images. Keep title separately validated, never interpolate it into SQL.

BM25 builds a bounded OR query from at most 32 Unicode word tokens, quoted/escaped as literals; punctuation-only returns zero candidates. Use FTS5 `bm25` ascending, chunk ID as tie-breaker; join active version/document/access conditions before LIMIT 20. Dense materialises only authorised active vectors, computes cosine via normalised NumPy dot product and returns descending score, chunk ID ties. This is exact search over <=2,000 rows; no approximate index needed. Hybrid sums `1/(60+rank)` for each candidate's 1-based BM25 and dense ranks, then sorts descending and retains 20. Reranker scores those 20 query/passage pairs, sorts by raw logit descending with chunk ID ties, selects 5. Plain BM25/dense/hybrid also return 5. Deduplicate chunks by ID, never by text across access scopes.

Profile `fixture` is the default: BM25 is real, dense uses a deterministic 384-dimensional SHA-256 token-hash embedding and reranker uses token overlap; both are labelled test doubles. Fixture generation is extractive: select up to 3 sentences containing query terms, copy exact text with numbered citations, abstain when no sentence has two non-stopword query terms. A short one-term query requires that term; the fixed stopword list is versioned. This answers only by quotation and is not described as an LLM. `local` generation in fixture profile returns 422 `mode_unavailable`.

Profile `local` uses the verified models below, snapshot-pinned during execution. BGE query instruction is `Represent this sentence for searching relevant passages: `; passages have none. Normalise embeddings and use CPU float32. Cross-encoder uses query/passage pairs and raw logits; do not interpret them as probabilities. The fixed generator is Qwen2.5-0.5B-Instruct with its chat template, CPU float32, `do_sample=False`, seed 17, maximum 2,048 input tokens and 256 output tokens. At most 5 passages fit in the context; drop whole lowest-ranked passages to meet budget. Require the model to return JSON `{answer, cited_chunk_ids, insufficient_evidence}`; schema failure, unknown citations or missing cited sources yields abstention with `invalid_generation`. Citation validity is mechanically checked; factual entailment is measured and manually reviewed, not guaranteed by valid IDs. Retrieved instructions are untrusted quoted evidence, have no execution channel, and cannot change access checks.

An index records its embedding backend/revision. A local request never reads fixture vectors: missing or mismatched revisions return `model_unavailable` until an explicit local rebuild succeeds. Switching the configured profile does not silently rebuild or reinterpret stored vectors.

The same generator/prompt/revision/budget and abstention policy are frozen across all four real retrieval runs. Evaluate extractive and local generation as separate report blocks. Retrieval metrics do not depend on generator output. Do not set model-specific score cutoffs using test labels; tune only on development and record chosen parameters, or report no threshold. Empty candidates always abstain. Corpus or question truncation counts are reported; the curated real benchmark requires zero embedding input truncations.

## Endpoints and errors

Additional public schemas: `SessionView(user_id: str, role: Role, csrf_token: str)`, `DocumentSummary(id: str, title: str, version_id: str, version_label: str, effective_date: str, revision: int)`, `DocumentView(DocumentSummary + text: str)`, `CitationView(Citation + section_text: str, section_start_char: int, highlight_start: int, highlight_end: int)`, and `JobView(id: str, status: JobStatus, error_code: str | None, created_at: str, updated_at: str)`. `JobStatus` is the six-state jobs-table enum. `VersionInput` and `ImportInput` have title/min_role/label/effective_date/markdown; `ReplaceInput` adds expected_revision; `RebuildInput` is an empty object. Dates validate as ISO dates, IDs as UUID except chunk hashes, titles 1-120 characters, labels 1-40 characters, revisions positive (a new document uses internal revision 0 before its first publish). `JobKind` is import/replace/rebuild.

- `GET /health` -> `{status:'ok', execution_profile:'fixture'|'local'}`; no authentication, no counts.
- `POST /api/session` `{code}` -> identity and CSRF token + session cookie; `GET /api/session` -> identity/CSRF; `DELETE /api/session` -> 204.
- `POST /api/questions` -> `Answer`; all retrieval/answer paths require valid sessions; no streaming in v1.
- `GET /api/citations/{chunk_id}` -> `Citation` plus complete current section text and highlight offsets relative to that section; checks current version and access again.
- `GET /api/documents` -> accessible active ID/title/version/date only; `GET /api/documents/{id}` -> accessible active metadata and escaped text.
- `POST /api/admin/documents` `{title,min_role,label,effective_date,markdown}` -> 202 `{job_id}`.
- `POST /api/admin/documents/{id}/versions` `{expected_revision,title,min_role,label,effective_date,markdown}` -> 202 `{job_id}`.
- `POST /api/admin/rebuild` `{}` -> 202 `{job_id}`; `GET /api/admin/jobs/{id}` -> status, generic error code and timestamps; `POST /api/admin/jobs/{id}/cancel` with `{}` -> JobView. Cancellation is idempotent for terminal jobs; queued/running jobs become cancelled, payload is cleared, and a late draft cannot commit. A supervisor terminates/joins any model subprocess owned by that job before releasing its lease.
- `DELETE /api/admin/documents/{id}` with `If-Match: <revision>` -> 204; mismatch 409; admin version history route `GET /api/admin/documents/{id}/versions/{version_id}` exposes only non-deleted retained text marked superseded.

All errors use `ApiError`: 401 `session_required`, 403 `forbidden` or `csrf_invalid`, 404 `not_found`, 409 `corpus_changed`/`revision_conflict`/`stale_job`, 413 `limit_exceeded`, 422 `invalid_input`/`mode_unavailable`, 429 `queue_full`, 503 `model_busy`/`model_unavailable`, 504 `model_timeout`. Malformed JSON follows the same 422 envelope, never stack traces. SQL busy becomes 503 `storage_busy`. Failed internal errors log only code/request ID, not input content. Client retries only an explicit user action; it never repeats delete/import automatically.

## Model provenance and resource lease

Primary cards checked on 2026-10-15: [BGE small](https://huggingface.co/BAAI/bge-small-en-v1.5) documents 384-dimensional embeddings, a 512-token sequence length and MIT licence; [MiniLM reranker card](https://huggingface.co/cross-encoder/ms-marco-MiniLM-L6-v2/raw/main/README.md) identifies the paired scoring model and Apache-2.0 terms; [Qwen card](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct/raw/main/README.md) identifies the 0.49B instruction model and Apache-2.0 terms. [Sentence Transformers](https://sbert.net/docs/cross_encoder/usage/usage.html) explains the reranker's logits. [SQLite FTS5](https://www.sqlite.org/fts5.html) defines its BM25 rank direction. These sources establish capabilities, not measured results for this application.

Bootstrap resolves immutable repository SHAs and file SHA-256 hashes into `config/models.lock.json`, saves licence notices and records the tested library/runtime versions. Download only required safetensors/tokenizer/config files into this project's cache, use `trust_remote_code=False`, and use `local_files_only=True` for every actual run. Never invent SHAs or silently change models. Missing snapshots return `model_unavailable`; network downloads are explicit CLI preparation, never an API side effect.

Before weight load, actual model evaluation or heavy indexing, atomically create `/tmp/bentolabs-portfolio-ml.lock` with `mkdir`; write `owner.json` containing project, PID, UTC start, purpose and a random owner token. Failure means busy: continue light tasks and return `model_busy` for that operation. No polling loop or automatic stale-lock removal. Inspect owner, process start and purpose before any manual recovery. A runner supervises the only model subprocess, kills and joins it on timeout/error/cancellation, and releases the lease only after all model processes exit and the stored owner token matches. The complete benchmark holds one lease for its duration. Models never stay resident after release. The API can remain running in fixture mode while another project holds the lease.

## Interface design

Use local system sans (`-apple-system`, BlinkMacSystemFont, Segoe UI, sans-serif), mono only for version IDs. Body 16/24 px; title 28/34, section 20/28, metadata 14/20; text measure 72ch. Spacing tokens 4,8,12,16,24,32,48 px, controls minimum 44 px, radius 8 px, borders 1 px. Desktop uses 2fr answer / 1fr evidence columns inside max-width 1,200 px; below 900 px stack them; at 360 px no horizontal scrolling. Use a separate full-page document view on mobile rather than a nested scrolling drawer.

Light: background #F5F6F8, surface #FFFFFF, text #17202A, muted #465466, border #CBD2DA, accent #155E75, danger #A11D2C. Dark: background #111820, surface #1B2531, text #F2F5F8, muted #B5C0CD, border #556577, accent #67D3EA, danger #FF9B9B. Test text and control contrast in both themes; focus ring 3 px visible with 2 px offset. Use a labelled theme selector respecting system preference initially; only theme is stored locally.

Top bar shows identity, profile, theme and sign out. Main question form has a visible label and retrieval/generation selectors. Answer always identifies quotation versus local generation. Citations are buttons/links with document/version/date; the viewer focuses its heading and highlights exact offsets without relying on colour alone. Admin page uses labelled forms and explicit Replace/Delete controls; deletion asks an in-app confirmation naming the fictional document. Loading/status uses aria-live=polite, errors role=alert, form errors connect via aria-describedby. Escape closes dialogs, focus returns to opener, tabs reach every control. Skeleton/panel transitions are <=120 ms opacity only; honour prefers-reduced-motion. No animated model output or fabricated progress percentages.

## Evidence and verification

CI installs frozen ordinary dependencies, blocks application network access, uses fixture profile and tests actual SQLite/FTS5. Model downloads and heavy runs are excluded. Strict Pyright includes `src`, `tests`, `scripts`; TypeScript checks `web/src`, component tests, `web/e2e`, Vite/Vitest/Playwright configs. Browser tests launch the actual API with a fresh temporary DB, log in through the code form, ask/open citation, switch roles, replace/delete and verify a stale link fails.

Retrieval recall@5 is relevant labelled sections retrieved / all relevant sections; MRR@5 is reciprocal first relevant section rank, or zero. Deduplicate repeated chunks of one section before metric calculation. Report each stratum and role with counts, mean, paired per-query differences and seeded bootstrap confidence intervals; do not select the final method from test performance. Manual review covers 24 test answers, balanced across methods (6 per method: 3 supported, 1 unsupported, 1 conflict, 1 restricted), with source text visible and method anonymised. Repeat that balanced review separately for each claimed generation block and report its small sample size. Citation support precision is supported cited claims / all cited claims; completeness is supported expected facts / expected facts; correct abstention is correct abstentions / unsupported-or-restricted cases. Store reviewer ID/date and disagreements; absent review leaves those fields unmeasured.

Release gates are behavioural: zero forbidden-string disclosure in the full regression matrix, 100% active-version citation resolution for emitted citations, no stale cache after mutation, completed offline verification. Quality metrics are reported, not promised to exceed invented thresholds. Real evaluation completion requires all four actual retrieval modes and fixed-generation report blocks or an exact missing-evidence statement. Commit only small reviewed reports in `reports/`; raw runs, prompts with private material, model weights and runtime databases stay ignored. `docs/STATE.md` remains the execution ledger.
